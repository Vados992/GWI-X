## Реальные данные Португалии — 30 октября 2026

Подключены открытые API **Eurostat, Banco de Portugal и ЕЦБ**: 15 успешных запросов, 41 годовой ряд за 2009–2025, 678 числовых значений и 19 явных пропусков. Средние ставки ЕЦБ получены из 6 209 реальных дневных наблюдений. Исходные ответы, даты, единицы, флаги и SHA-256 сохранены; пропуски остаются `NULL`. [Подробный отчёт на русском](docs/real_data_validation_ru.md).

**Бухгалтерские проверки прошли; национальная модель реформы пока не валидирована.** В 34 проверках сошлись бюджетные и национальные тождества. На 2019–2024 годах средняя ошибка роста ВВП текущего ядра — 5,29 п.п. против 4,88 у нулевого роста; для безработицы и инвестиционного приближения ядро также хуже простого ориентира. HICP на этой небольшой выборке лучше ориентира. Это ретроспективные годовые шаги по пересмотренным данным, без введения реформы и без доказательства её причинного эффекта.

Реальные индивидуальные микроданные, национальный налогово-социальный модуль и подтверждённое финансирование отсутствуют. Публичные микрофайлы EU-SILC синтетические и не использованы как наблюдения. Неизвестные ресурс программы и резерв — `null`; полный национальный запуск возвращает **2 / BLOCKED**. [Матрица необходимых источников и доработок](docs/real_data_validation_ru.md#что-подключено-и-что-ещё-требуется).

```text
python -S -m gwix.official validate --out results-local/official-check
python -S scripts/verify_official.py --out results-local/official-replay
python -S -m gwix.official fetch --out results-local/fresh-official-snapshot
python -S -m gwix.official run-policy
```

Только `fetch` требует сеть. Код 0 команды `validate` означает успешную проверку данных и счетов; он не означает пригодность модели для национальной реформы. Все папки вывода должны быть новыми. При ошибке API `fetch` сохраняет протокол и возвращает 2 без синтетической подстановки.

## Отдельная синтетическая лаборатория v1.2

**SYNTHETIC / НЕ ДАННЫЕ СТРАНЫ / НЕ ПРОГНОЗ.** Материалы `configs/synthetic.json`, `results/`, `sensitivity/` и исходный PDF относятся к синтетической лаборатории. Три исполняемые модели связаны общими потоками денег, доходами и годовыми состояниями. Горизонт этого расчёта — 2027–2036 годы. Это реализация проверяемой части архитектуры GWI-X v1.2, а не государственная платёжная система. Исходный [синтетический архив](releases/GWI-X-v1.2.zip) сохранён отдельно и не содержит нового подключения данных.

В комплекте: исходный Python-код, JSON-конфигурация, синтетическая микровыборка, результаты восьми сценариев и их контролей, тесты, независимая сверка CSV, анализ чувствительности, графики и [технический отчёт на русском](docs/technical_report_ru.md).

Для чтения подготовлена также [PDF-версия отчёта](docs/technical_report_ru.pdf). Её необязательное повторное создание: `python scripts/build_pdf.py` после генерации PNG; нужны ReportLab 4.5.0 и TrueType-шрифты с кириллицей. На другой системе пути к обычному и жирному шрифту передаются через `--font` и `--bold`. Эти зависимости не нужны для расчётов, тестов, CSV, SVG и текстового отчёта.

## Запуск

Нужен Python 3.11 или новее. Расчёты, тесты, CSV и SVG работают **только на стандартной библиотеке**; установка пакетов и доступ к сети для них не нужны. Команды выполняются из этой папки после распаковки архива.

```text
python -m unittest discover -s tests -v
python -m gwix all --config configs/synthetic.json --out results-local/new-run
python scripts/audit_csv.py results-local/new-run
```

Windows: `run.ps1` запускает тесты и сохраняет новый расчёт в отдельной папке с датой. Существующие результаты не перезаписываются. Если политика Windows запрещает сценарии PowerShell, используйте команды Python выше.

Один сценарий:

```text
python -m gwix run --scenario reform --out results-local/reform
python -m gwix run --scenario zero_funding --out results-local/no-funding
```

При остановке одиночного расчёта по нехватке финансирования возвращается код **2**, а причина записывается в `status.json`. Команда `all` возвращает 0 после формирования диагностического набора, в котором остановленные стрессы ожидаемы. **Код 0 команды `all` не означает, что все сценарии финансово устойчивы.** Читайте `results/summary.csv` и статусы отдельных сценариев.

Графики в SVG создаются всегда. Для дополнительных PNG можно установить необязательный пакет `Pillow==12.2.0`; поставленные PNG уже готовы. Основные численные результаты не зависят от Pillow.

```text
python -m gwix sensitivity --out results-local/sensitivity
python scripts/build_report.py
python scripts/package.py ../GWI-X-v1.2.zip
```

Последняя команда собирает архив и SHA-256; отчёт строится из поставленных `results/` и `sensitivity/`. Сценарии с изменённой конфигурацией храните отдельно: исходный отчёт описывает именно поставляемую конфигурацию.

В архиве всегда используется папка `GWI-X-v1.2`, независимо от имени клонированного репозитория. `releases/` хранит готовый пакет для скачивания и не включается в него повторно. Манифест описывает исходники и расчётные материалы, исключая историю Git, локальную среду, `results-local/` и готовые архивы. SHA-256 самого ZIP хранится рядом с архивом.

GitHub Actions проверяет проект на Windows и Linux. Проверки исполняют весь расчёт дважды, независимо сверяют денежные тождества и опубликованные CSV; установка библиотек для расчётного ядра не требуется. Фактический статус текущей версии виден в значке проверки сверху. [Правила внесения изменений](CONTRIBUTING.md) · [История версий](CHANGELOG.md).

## Что действительно реализовано

| Модуль | Расчёт |
|---|---|
| `gwix/households.py` | 1200 синтетических домохозяйств с весами до 1 млн семей; работники, самозанятые, семьи с детьми, одинокие родители, пенсионеры и группа инвалидности; занятость отдельных взрослых; налоги, взносы, пособия, валовой, чистый и реальный доход; предельные ставки каждого работающего взрослого |
| `gwix/fiscal.py` | Национальные денежные потоки, долг, казначейские деньги, ликвидный резерв; Income Fund, Social Insurance Clearing, Productive Capacity Fund, Stability Reserve; консервативное покрытие новых назначений на оставшийся горизонт |
| `gwix/macro.py` | Потребление, инвестиции, производительный капитал, TFP, потенциальный и фактический выпуск, CPI; зарплаты с задержкой индексации, спрос и переходы занятости следующего года |
| `gwix/engine.py` | Годовой порядок связи модулей; ограничения по долгу, финансированию, дополнительной инфляции, занятости и групповым реальным доходам; контрольный сценарий с теми же шоками |

Включение реформы не уменьшает договорную ставку или часы и не повышает прямую ставку взносов работодателя. Это свойство правил модели при одинаковом контракте. Общая зарплатная ведомость может измениться из-за занятости, цен и динамики заработка; неизменность издержек бизнеса в реальности не доказана.

## Финансирование и ограничения

Источником программы служит **сокращение существующего условного пула субсидий фирмам**, до 2 млрд CU в ценах базового года ежегодно. Это перераспределение: источник не добавляется повторно к национальным налоговым доходам. Неиспользованные средства возвращаются казначейству. Прогнозная экономия и будущие эффекты производительности не считаются текущим покрытием.

Начальный резерв — 0,8 млрд CU, казначейские деньги — 0,5 млрд CU, долг — 60 млрд CU. Исторически назначенная начальная группа защищённых получателей задана как начальное условие. Обычный государственный дефицит допускается только при явно рассчитанном заимствовании в пределах лимитов либо при расходовании имеющихся казначейских денег. Резерв программы отдельно покрывает её существующие обязательства.

При нехватке денег расчёт останавливается **перед записью не обеспеченного финансированием года**. Модель не обнуляет обязательства, не выдумывает новые доходы и не вводит денежную эмиссию. Это диагностическая остановка, а не решение о прекращении законных прав.

Ставки налогов, права на пособия, финансовый ресурс и доступ к заимствованиям в этой лаборатории — синтетические допущения. Доступа к казначейским счетам, платёжным каналам, EUROMOD или персональным реестрам нет. Отдельное подключение открытых агрегатов и историческая диагностика Португалии описаны выше; они не доказывают снижения инфляции или роста занятости от реформы.

## Результаты и проверка

- `results/summary.csv` — завершённость сценариев и финансовые разрывы.
- `results/comparisons.csv` — отличия реформы от контроля с теми же шоками.
- `results/<scenario>/annual.csv` — национальные бюджетные и макроэкономические величины.
- `results/<scenario>/households.csv` — доходы, занятость и предельные ставки семей по годам.
- `results/<scenario>/groups.csv` — раздельные итоги шести групп.
- `results/<scenario>/funds.csv` — потоки четырёх назначений и внутренние переводы.
- `results/controls/<scenario>/` — соответствующий вариант без реформы.
- `results/inputs/` — синтетические исходные записи и происхождение данных.
- `sensitivity/sensitivity.csv` — девять комбинаций эффективности инвестиций и чувствительности цен.
- `verification/` — протоколы тестов, независимой сверки и повторного исполнения.
- `manifest.json` — SHA-256 файлов поставки; ZIP дополнительно имеет внешний SHA-256.

CSV: UTF-8, разделитель — запятая, десятичная точка. Пустая предельная ставка означает «не определена: нет работающего взрослого», а не нулевую ставку. В `emtr_adults` отдельные значения перечислены через `;`, `NA` означает отсутствие показателя. Вес семьи применяется **ровно один раз**, только при получении национальных агрегатов.

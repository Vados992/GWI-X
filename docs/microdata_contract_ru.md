# Локальный контракт наблюдаемых микроданных Португалии

Статус: **интерфейс учётного аудита реализован и испытан на синтетических тестовых фикстурах; настоящая лицензированная микровыгрузка не получена и не проверена**. Он не подключает EUROMOD и не вычисляет португальские права на выплаты или EMTR.

Нужен законно полученный исследовательский EU-SILC scientific-use file либо национальная выборка. Публичный учебный EU-SILC полностью синтетический и отвергается. Из исходных D/H/R/P-файлов владелец/исследователь должен подготовить сопоставленную годовую выгрузку по описанному ниже определению дохода. Автоматического универсального преобразования всех волн EU-SILC в этом проекте нет.

Храните вход и метаданные внутри `private-data/` или вне репозитория. `private-data/` исключён из Git, манифеста и ZIP. В поставке присутствуют только публичные агрегаты. Учётный аудит сохраняет суммарный результат без идентификаторов семей и не разблокирует национальный запуск.

## CSV

Кодировка UTF-8, запятая, десятичная точка, одна строка на домохозяйство и год дохода. Дополнительные колонки, включая имена и контакты, не допускаются. Обязательные поля:

| Поле | Определение |
|---|---|
| `household_id` | Псевдонимный код, уникальный вместе с годом, не ФИО/номер документа |
| `year` | Год дохода, не год обследования |
| `weight` | Положительный вес домохозяйства; применяется один раз |
| `group` | Непустая заданная исследователем группа; определения и перекрытия должны быть документированы |
| `adults`, `children`, `employed_adults` | Целые счётчики; число занятых не превышает число взрослых |
| `gross_earnings_eur` | Наблюдаемые валовые трудовые поступления за год, неотрицательные |
| `other_income_eur` | Прочие доходы по согласованному определению; возможны убытки |
| `income_tax_eur` | Наблюдаемый подоходный налог, неотрицательный |
| `employee_contributions_eur` | Наблюдаемые личные обязательные взносы, неотрицательные |
| `cash_benefits_eur` | Денежные социальные выплаты, неотрицательные |
| `disposable_income_eur` | Годовой располагаемый доход по тем же компонентам |

Проверяется `gross_earnings + other_income − income_tax − employee_contributions + cash_benefits = disposable_income` с допуском 0,02 EUR на семью. Выгрузка, для которой исходные определения не соответствуют этому тождеству, должна быть согласована с владельцем данных, а не автоматически исправлена. Неизвестные компоненты не подставляются как нули; такой файл не проходит канонический аудит.

## Метаданные JSON

Обязательны `data_origin: "OBSERVED_LICENSED_MICRODATA"`, `country: "PT"`, `income_year`, `source_owner`, `license_reference`, `income_definition`, `coverage_definition` и SHA-256 CSV в поле `sha256`. Это утверждения поставщика о происхождении и лицензии; программа не удостоверяет их юридическую подлинность. Год и SHA проверяются автоматически.

```text
python -S -m gwix.official micro-audit --input private-data/households.csv --metadata private-data/provenance.json --out private-data/accounting-audit.json
```

До микросимуляции дополнительно нужны национальные правила конкретного года, информация о налоговых единицах, всех видах доходов, возрасте, имущественных тестах, инвалидности, пенсионных правах и рабочих часах. Пара наблюдаемых «валовой/чистый доход» не определяет предельную ставку: EMTR требует повторного вычисления налогов/пособий при малом изменении заработка. Эти пробелы не скрываются формальным успехом учётного аудита.
